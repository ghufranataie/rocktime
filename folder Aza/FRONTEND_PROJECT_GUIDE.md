# RockTime / ShowTime — Frontend Guide

## 1) Что это за проект и зачем он нужен

Это frontend-платформа для продажи билетов на события (концерты, театр, комедийные шоу).  
Цель продукта: дать пользователю простой путь от выбора события до оплаты через Stripe.

Ключевая ценность:
- быстро найти событие;
- выбрать конкретные места;
- оформить заказ и оплатить безопасно через Stripe Checkout;
- хранить аккаунт и видеть свои билеты.

---

## 2) Что видит пользователь (основной UX)

### Главный пользовательский сценарий
1. Пользователь открывает главную страницу `/`.
2. Переходит в каталог `/events` и фильтрует события.
3. Открывает карточку события `/event/:id`.
4. Выбирает места (seat map) и добавляет билеты в корзину.
5. В корзине `/cart` проверяет состав заказа и итоговую сумму.
6. На `/checkout` вводит контактные данные.
7. Переходит в Stripe Checkout и оплачивает.
8. После возврата получает успешный экран подтверждения.

### Что доступно пользователю
- Поиск событий по названию/артисту.
- Фильтры по жанру, цене и доступности.
- Выбор мест в зале.
- Корзина с пересчётом subtotal + tax/fees.
- Авторизация/регистрация.
- Личный кабинет с загрузкой билетов пользователя.
- Информационные страницы About/Contact.

## 3) Маршруты frontend

Определены в `src/App.tsx`:

- `/` — главная (`Index.tsx`)
- `/events` — список событий (`Events.tsx`)
- `/event/:id` — детальная страница события (`EventDetail.tsx`)
- `/cart` — корзина (`Cart.tsx`)
- `/checkout` — checkout + Stripe редирект (`Checkout.tsx`)
- `/auth` — вход/регистрация (`Auth.tsx`)
- `/account` — профиль и билеты (`Account.tsx`)
- `/admin-auth` — вход администратора (`AdminAuth.tsx`)
- `/admin` — админ-панель (`Admin.tsx`)
- `/about` — о проекте (`About.tsx`)
- `/contact` — контакты (`Contact.tsx`)
- `*` — 404 (`NotFound.tsx`)

Особенность layout:
- `Navbar` и `Footer` скрываются в admin-зоне (`/admin...`).

## 5) Данные и состояние на клиенте

### Корзина
`CartContext.tsx` хранит:
- позиции корзины (событие, выбранные места, цена);
- методы `addItem`, `removeItem`, `clearCart`;
- вычисляемые `totalItems`, `totalPrice`.

### LocalStorage (важные ключи)
- `showtime_user` — текущий пользователь.
- `showtime_users` — локальный каталог известных пользователей.
- `showtime_tickets` — купленные билеты (локальный слой).
- `showtime_pending_order` — заказ перед переходом в Stripe.
- `showtime_taken_seats` — занятые места по событиям.
- `showtime_admin_session` — admin-сессия.
- `showtime_admin_events` — локально созданные admin-события.

## 6) Интеграции с API и Stripe

Frontend работает с AWS API Gateway (base URL в коде: `https://f3nnaj8z43.execute-api.us-east-1.amazonaws.com/dev`, либо через `VITE_API_BASE_URL`).

Используются endpoint’ы:
- `GET /events` — загрузка событий.
- `POST /events` — создание событий (админ).
- `POST /auth` — логин пользователя.
- `POST /register` — регистрация пользователя.
- `GET /users` — список пользователей (админ).
- `GET /tickets` — билеты (общие, по юзеру, по событию).
- `POST /adminAuth` — вход администратора.
- `GET /founders` — команда на странице About.

### Stripe в checkout
Checkout использует:
- `VITE_STRIPE_CHECKOUT_ENDPOINT` (fallback на `/checkout` endpoint API Gateway).
- Создаёт `pending_order` в localStorage.
- Отправляет payload и делает редирект на Stripe URL.
- После возврата с `?stripe=success`:
  - фиксирует покупку;
  - резервирует места;
  - очищает корзину;
  - показывает экран подтверждения.

## 7) Пользовательские роли

### Обычный пользователь
- может смотреть каталог и детали событий;
- выбирать места и покупать билеты;
- входить/регистрироваться;
- видеть свои билеты в `Account`.

### Администратор
- логин через `/admin-auth`;
- доступ к `/admin`:
  - создание нового события;
  - просмотр пользователей;
  - просмотр билетов (все/по событию/по пользователю).

## 8) Сильные стороны текущего frontend

- Чёткий и понятный user flow (discover → select seats → cart → checkout).
- Реальный Stripe checkout-процесс с редиректом.
- Разделение user/admin сценариев.
- Достаточно чистая структура по папкам и ответственности.
- UI ориентирован на мобильный и desktop (адаптивный layout).

---

## 9) Что важно понимать при развитии

- Часть состояния (корзина/билеты/места) хранится локально, поэтому это не полностью сервер-источник истины.
- Часть данных приходит с API, часть поддерживается в localStorage (гибридный подход).
- Для production-масштаба стоит унифицировать источник данных (server-first) и добавить более строгую валидацию статусов оплаты/webhook-сценариев.

## 10) Короткий итог

Frontend RockTime/ShowTime — это готовый клиентский интерфейс тикетинг-сервиса:
- витрина событий,
- выбор мест,
- корзина,
- checkout с Stripe,
- аккаунт пользователя,
- admin-интерфейс для операционного управления.

Документ предназначен для быстрого онбординга: новый разработчик или стейкхолдер может за 10–15 минут понять, зачем нужен продукт, как он работает и где находится ключевая логика.
